# 3-part first-principles block (paste into a step)

Use one block per key term. Part 1 is one sentence.

```markdown
### <term>

**1. What it is (first principle).**
<one sentence anyone can repeat. Name the job, not the brand.>

**2. Adjacent terms (same family, different packaging).**
- `<cousin>` — same primitive: … / different: …
- `<cousin>` — …
Why the names differ: <one sentence>.

**3. Variations grounded to that primitive.**
Stay on this job:
- <next file / flag / tool that does the same job>
- <next place to look>
- <tool that makes this job faster>
```

### Command variant

```markdown
**Command**

\`\`\`bash
<exact command run>
\`\`\`

**1. What the tool is.**
<one sentence: the job of the binary>

**2. Adjacent tools.**
- <cousin tool> — same job, different default (e.g. rustscan vs nmap)

**3. Flags used (each one is a variation of “ask the tool one extra question”).**

| Piece | Meaning |
|-------|---------|
| flag | what extra question it asks |
```
